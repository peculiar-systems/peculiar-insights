# Peculiar Insights

Self-hosted product analytics and crash tracking. A Haskell server ingests
events, profiles, crash reports and consent records over gRPC, gRPC-Web and
Connect; PostgreSQL stores them; Grafana is the entire frontend. SDKs exist
for Flutter, TypeScript and Haskell, and each one is built so that consent,
data minimisation and erasure are the default path rather than an add-on.

The product decisions behind every part of this are in `DECISIONS.md`.

## Layout

| Path | What it holds |
|---|---|
| `proto/` | The contract, `peculiar.insights.v1`, single source of truth for every language |
| `backend/core/` | The pure model: validation, consent enforcement, clock-skew correction, crash fingerprinting, cohort SQL, profile and issue transitions |
| `backend/server/` | The ingest server: beam schema, migrations, the reporting and admin SQL, gRPC handlers, maintenance |
| `backend/inventory/` | The data inventory and Apple privacy manifest, generated from proto annotations |
| `sdk/dart/` | The Dart core and the Flutter plugin |
| `sdk/ts/` | The TypeScript package with browser and node entry points |
| `sdk/haskell/` | The Haskell client for backend services |
| `grafana/` | Provisioned dashboards and alert rules |
| `nixos/module.nix` | The service, PostgreSQL and Grafana provisioning as one NixOS module |

## Development

Everything is a Nix task and `nix flake check` is the only gate.

```
nix run .#tasks-help     every task
nix run .#codegen        materialise generated protobuf code for editors
nix run .#inventory      regenerate PRIVACY.md and the privacy manifest
nix run .#fmt            format Haskell and Nix
nix run .#lint           hlint with the shared ruleset
nix flake check          build, test, format, lint, proto lint
```

The server test suite starts an ephemeral PostgreSQL inside the check, so
no database needs to exist on the machine running it.

## Deploying

Import the flake's `nixosModules.default` and declare projects, from the
Insights host's configuration or from each product's own module. Keys are
generated by the service unless a path is given; TLS material is always a
path to a file delivered out of band, never a value.

```nix
services.peculiar-insights = {
  enable = true;
  projects.shop.environments.prod = {
    retentionDays = 400;
    cohorts.payers = [
      { did_event = { event = "purchase"; at_least = 1; within_days = 30; }; }
    ];
    analytics.funnels.checkout = {
      steps = [ "checkout_opened" "order_placed" ];
      windowDays = 7;
    };
  };
};
```

With the defaults the module runs PostgreSQL, creates the database and the
`grafana` reader role, provisions the datasource, the shared dashboards and
the alert rules into the host's Grafana, generates the ingest key under its
state directory and exports its path as
`services.peculiar-insights.keyFiles."shop/prod"` for other services on the
host, and gives the environment its own Grafana folder with a dashboard
built from its funnels, retention, metrics and cohorts. A Grafana Admin
resolves, ignores and reopens issues from the issue detail dashboard and from
each row of the crashes list, and erases the selected person from the people
dashboard after confirming; the server refuses anyone else.

Every key has a rate limit, and a throttled SDK keeps what it was sending
and retries when the server says to. With `monitoring.enable` the server
serves its own counters at `/metrics`.

## Consent

The SDKs persist nothing and open no connection until a purpose is granted.
Two purposes exist, analytics and diagnostics. Every batch carries the
consent snapshot and the server refuses items whose purpose is not granted,
so a defective client cannot store unconsented data. `PRIVACY.md` lists every
collected field with its category and purpose and is regenerated from the
proto, as is the Flutter plugin's `PrivacyInfo.xcprivacy`.

## Known gaps

- The Flutter plugin is analyzed and tested with the local Flutter toolchain,
  not inside `nix flake check`, because no Flutter SDK derivation is wired
  yet. The pure Dart package is gated.
- Persistence on Flutter web needs the drift wasm assets served by the app;
  without them the SDK falls back to in-memory storage.
- Performance monitoring is a later phase, as `DECISIONS.md` records.
